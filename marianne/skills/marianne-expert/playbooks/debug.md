# Debugging Failures

## Problem

Debugging Marianne failures goes wrong when the operator treats the visible symptom as the system boundary. A failed validation can be a real artifact defect, a trusted-author shell failure, a process-group safety refusal, or a stale assumption about a feature that is only specified, not executed. Validation path templates use Python single-brace `.format()` expansion, while prompt rendering uses deferred Jinja2 double-brace rendering at dispatch time; mixing those syntaxes can make an artifact look absent even when the prompt looked correct. [C001, C002, C003] Validation commands are implemented, but `command_succeeds` is a privileged bash execution surface for trusted score authors, so debugging must include the trust boundary before rerunning or copying commands. [C015] Error taxonomy is another common source of false triage: `ErrorCode.category` is parsed from the first numeric digit after `E`, so E0xx is execution, E1xx rate limit, E2xx validation, E3xx configuration, E4xx state, E5xx backend, E6xx preflight, and E9xx transient by implementation inference from the category map. [C047]

## Mechanism

Start with the highest-authority artifact you have: executable code and tests beat docs, generated evidence beats prose, and stale comments describe drift rather than behavior. The debug path is: classify the failure, identify the boundary, verify whether the feature is implemented, then choose retry or escalation. Validation has exactly nine retryable validation types: `file_exists`, `file_modified`, `content_contains`, `content_regex`, `command_succeeds`, `path_in_scope`, `field_match`, `file_sha256`, and `csv_unique_key`. [C015] A retry is appropriate when the failed surface is one of those retryable validation types and the failure can be caused by missing output, late output, regex mismatch, command exit, path expansion, hash mismatch, or duplicated key. [C015] A retry is not appropriate when the failure points at a contradicted runtime claim: `CronTick` only logs an unimplemented warning and does not submit or reschedule jobs, `ConfigReloaded` only logs an unimplemented warning and does not rebuild pending sheets, grounding config validates structurally but runtime does not invoke grounding hooks, and orphan reaping is a hardcoded safety no-op rather than an operator-toggleable cleanup system. [C029, C030, C031, C032, C033]

For E0xx execution failures, inspect process lifecycle, subprocess output, dispatch state, and capture truncation before changing score logic. Command validation spawns with `start_new_session=True`, refuses a child that shares the daemon process group, and terminates the process group with SIGTERM, a two-second grace period, then SIGKILL. [C016, C017, C018] For E1xx rate-limit failures, inspect dispatch gates: `dispatch_ready()` checks instrument rate-limit state and also enforces global, per-instrument/model, and stagger constraints. [C005, C006, C007, C008] For E2xx validation failures, inspect the validator’s exact type and the syntax boundary between `.format()` validation paths and Jinja prompt variables. [C001, C002, C003, C015] For E3xx configuration failures, inspect prompt config and path resolution; `PromptConfig` rejects simultaneous inline `template` and `template_file`, and relative workspace paths resolve against the score file parent without confinement, which is security-sensitive for untrusted scores. [C038, C039] For E4xx state failures, inspect checkpoint schema/state boundaries: job status has seven states, sheet status has eleven states, outcome category has six categories, and SQLite state schema version is 4. [C041, C042, C043, C044] For E5xx backend failures, check the actual backend path: `recursive_light` uses the generic OpenAI-compatible/OpenRouter path, while only `AnthropicApiBackend` and `OllamaBackend` remain as specialized native clients. [C021, C023, C024, C025]

## Evidence

The runtime classifies error categories from `value[1]`, the first numeric digit after `E`; the docs or original claim saying the second digit is false. Treat E0xx-E5xx mapping as an implementation-derived debugging shortcut and cite C047 whenever using it. [C047] The validation engine’s retry surface is bounded by the nine implemented retryable types, so an automatic retry should be justified by one of those types rather than by general hope that a rerun will pass. [C015] The validation command runner is deliberately robust around process groups: it starts commands in a new session, guards against daemon process-group sharing, and kills the group on timeout or exit cleanup. [C016, C017, C018]

Dispatch failures have their own evidence cluster. `dispatch_ready()` is a stateless free function, enforces a global concurrency ceiling despite one stale configuration reference, supports per-instrument/model limits, checks rate-limit state, and applies a monotonic-clock stagger gate. [C004, C005, C006, C007, C008] The docs say global concurrency is not enforced, but source/tests show `dispatch_ready()` enforces it. Treat the implementation as runtime truth and record the configuration-reference line as stale. [C005]

Spec-only and runtime-unwired surfaces require escalation or re-scoping, not retries. The docs say `CronTick` schedules jobs, but source/tests show the handler only logs an unimplemented warning. Treat warning-only behavior as runtime truth and record scheduling prose as stale. [C029] The docs say `ConfigReloaded` rebuilds pending sheets, but source/tests show it only logs an unimplemented warning. Treat the warning as runtime truth and record live-reload prose as stale. [C030] The docs say grounding hooks validate outputs, but source/tests show runtime never invokes them. Treat configuration validation as runtime truth and record active grounding as stale. [C031] The docs say orphan cleanup has a module-level disabled flag, but source/tests show inline no-op methods. Treat the no-op as runtime truth and record the flag claim as false. [C033]

## Trap

Tempting sentence: “The score looked right, so the failure must be transient.” Corrected sentence: prompt rendering and validation path expansion use different syntaxes and lifecycle points, so check `.format()` paths separately from Jinja prompts before retrying. [C001, C002, C003]

Tempting sentence: “A validation command failed; just rerun it.” Corrected sentence: `command_succeeds` is privileged bash for trusted score authors, process-group guards can refuse unsafe children, and a failed command may be an actual safety signal. [C015, C016, C017, C018]

Tempting sentence: “Cron, config reload, grounding, and orphan cleanup are available because they are documented.” Corrected sentence: these are spec-only, runtime-unwired, or known-broken safety no-op surfaces; retries cannot make them execute. [C029, C030, C031, C032, C033]

Tempting sentence: “E217 means category 1 because the second digit is 1.” Corrected sentence: the implementation reads the first numeric digit at `value[1]`; E217 is validation because the category digit is `2`. [C047]

## Verify

Before declaring root cause, run this checklist. First, record the exact error code and classify it by the first numeric digit after `E`; if your category depends on the second digit, it is wrong. [C047] Second, identify whether the failure is a retryable validation type and name the exact validator; if it is not one of the nine retryable validation types, do not describe retry as the default recovery. [C015] Third, if `command_succeeds` is involved, inspect command text, working directory, exit status, timeout, captured output, and process-group behavior; the runner uses a new session, refuses daemon process-group sharing, and sends SIGTERM then SIGKILL to the command group. [C016, C017, C018]

Fourth, check for looks-right-but-isnt traps: single braces belong to validation path `.format()` expansion, double braces belong to deferred Jinja prompt rendering, and score-relative paths are not confined against `..` or absolute path escape. [C001, C002, C003, C038] Fifth, when output appears incomplete, remember output capture uses 51,200 bytes / 50 KiB and keeps the trailing output; a stale 10KB test docstring is not runtime truth. [C048] Sixth, if a failure mentions dispatch, inspect global concurrency, per-instrument/model concurrency, rate limit, and stagger gates before blaming the backend. [C005, C006, C007, C008]

Escalate instead of retrying when the suspected fix depends on a feature whose status is `spec_only`, `config_only_runtime_unwired`, `known_broken_safety_noop`, or contradicted by source. `CronTick`, `ConfigReloaded`, grounding hooks, and orphan cleanup fall into those categories. [C029, C030, C031, C032, C033] Escalate also when a backend diagnosis relies on broad “native backend” wording: `recursive_light` is generic OpenAI-compatible/OpenRouter, and the specialized native clients are Anthropic and Ollama only. [C021, C023, C024, C025] Retry only after the boundary is named, the claim IDs are cited, and the next run can plausibly produce a different result without inventing a runtime feature.
